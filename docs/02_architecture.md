# 02. 시스템 아키텍처 (설계안)

## 전체 구성
```text
[Windows PC: Electron + React/TypeScript]
    ├─ 화면 계층: 홈 / AI 게임 만들기 / 내 게임 / 설정
    ├─ 안전한 IPC(API 목록 제한, 입력 검증)
    ├─ 작업 관리자(상태 전이, 중지/복구, 작업 예산)
    │    ├─ 기획 역할 ─┐
    │    ├─ 개발 역할 ─┼─ 단일 로컬 AI 모델 (Ollama, 순차적 역할 전환)
    │    └─ 테스트 역할┘
    ├─ 제한된 Godot 제작 도구/템플릿 + 작업본
    ├─ 프로젝트 매니저: 작업 로그/복구 지점/검증
    ├─ SQLite: 로컬 메타데이터 / 작업 이력
    └─ 허용된 게임 실행기(별도 격리·보안 실험 필수)
             │ 인증된 HTTPS 연결 (4단계 이후)
[온라인 백엔드: Node.js + TypeScript 제안]
    ├─ 인증 서비스(이메일, Google OAuth/OIDC)
    ├─ 권한/공유/게임 검색 API
    ├─ 심사/신고/운영 관리 서비스
    ├─ PostgreSQL: 계정·권한·게임 메타데이터
    ├─ 객체 저장소: 승인된 프로젝트·에셋·백업
    └─ (5단계) 친구·채팅·방 관리 / 멀티플레이 세션
```

## 설계 판단
- **클라이언트**: Electron+React+TypeScript는 화면과 로컬 실행 조정을 분리하기 수월하나, 브라우저 UI에서 시스템 파일 명령을 직접 실행하지 못하게 한다. `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true`, 제한된 `preload`, CSP 및 IPC 호출자 검증을 기본 설계 요건으로 삼는다.
- **게임 엔진**: Godot 4.x 표준(GDScript 경로)을 우선 기술 실험. 2026-11-17 공식 안정 릴리스 4.7.2, 베타 4.8은 기본 채택 보류. 버전 잠금은 샘플 프로젝트 호환성 시험 후.
- **로컬 AI**: Ollama를 후보로 하되 설치/설치 취소/건전성 검사, localhost만 접속, 무결성·라이선스 확인. 모델별 PC 자원 및 품질을 실측하기 전 기본 모델 확정 금지.
- **데이터**: 로컬 SQLite에는 게임 목록/상태/로그 메타데이터, 실제 게임 파일은 별도 프로젝트 폴더. 서버 PostgreSQL에는 계정/권한/게시물 메타데이터, 객체 저장소에는 업로드 파일. 인증 비밀은 OS 자격 증명 보호 기능 활용 검토.
- **서버**: 처음에는 계정/게임/심사 API를 모듈식 단일 백엔드로 제안(운영 단순화). 추후 채팅/실시간 게임방만 필요 시 분리. 서버 제공자는 아직 미선택.

## 작업 관리자 및 안전한 제작 파이프라인(3단계 목표)
1. 사용자 요구를 간단한 제작 의도로 구조화(기획 역할).
2. 검증된 장르 템플릿과 허용된 도구를 우선 선택.
3. 기존 파일이 아닌 **작업 사본**에 변경 적용(개발 역할).
4. 프로젝트 구조/스크립트 제한/실행 검사/테스트 실행(테스트 역할).
5. 검증되면 원자적 교체 및 복구 지점 생성; 실패하면 작업 사본 폐기·기존 정상본 보존.
6. '동작 확인됨'과 '요청 기능 구현됨'은 별도 상태로 표시.
7. 파일 접근 루트, 실행 가능한 명령, 네트워크·시간·메모리·재시도 횟수를 화이트리스트로 통제.

**중요**: AI가 생성한 코드나 다른 사용자가 업로드한 게임은 신뢰할 수 없다. Godot 자체 실행만으로 안전한 격리가 제공된다고 가정하지 않는다. Windows용 제한된 계정·프로세스 격리·파일시스템 경계·네트워크 정책 등을 별도 실험·침투 테스트로 검증해야 하며, 이를 통과하기 전 타인 게임 실행 기능 공개 금지.

## UI 원칙
- 첫 화면은 쉬운 사용자 언어로 구성: '어떤 게임을 만들고 싶나요?'.
- 전문 옵션은 고급 설정으로 숨긴다.
- 상태는 '준비 중 / 만드는 중 / 확인 중 / 수정이 필요해요 / 완료'로 설명하고 정지·재시도·복구 경로 표시.
- 1단계에서는 제작 버튼을 비활성화하거나 명확히 '준비 중'으로 표시(가짜 성공 금지).

## 기술 선택을 바꿀 기준
- Electron 메모리 사용·Windows 호환 문제가 기준을 넘을 경우 Tauri 대안 실험(러스트 역량과 개발비 비교).
- Ollama 모델 품질/성능 부족 시 다른 로컬 런타임 후보 실험; 사용자의 로컬 AI 정책은 유지.
- 멀티플레이는 서버형·사용자 호스트형 모두 미정, NAT/치트/지연/비용 테스트 후 선택.
