# 03. 구현 로드맵 (승인 단위)

> 개발 단계 1~5는 사용자가 요청한 작업 순서. 원문 P0/P1/P2는 출시 단계를 뜻하므로 동일한 번호 체계가 아니다. 날짜·예산은 미정.

| 개발 단계 | 주요 산출물 | 다음 단계 이동 문턱 |
|---|---|---|
| 1. Windows 앱 기본 구조 | Electron 셸, 4개 메뉴, 폴더 구조, 실행/화면 테스트 | 실제 Windows에서 실행·이동 확인, 보안 설정 검사 |
| 2. 로컬 AI 연동 | PC 사양 검사, 모델 설치 동의·선택, 채팅 및 진행 표시 | 로컬 요청·취소·오류 회복, 모델/자원 실측 |
| 3. Godot 제작 | 2D/3D 각 1개 템플릿, 자연어 생성/수정, 미리보기, 복구 | TEST-001~003, 보안 경계/파일 안전 시험 통과 |
| 4. 온라인 플랫폼 | 이메일/Google 로그인, 계정, 무료 게임 공개·권한, 심사·신고 | 미인증 접근 차단, 서버 권한, 업로드 검사, 아동·법률 출시 조건 |
| 5. 커뮤니티·멀티플레이 | 친구·차단·텍스트 채팅, 방, 리믹스, 선택 백업 | TEST-007~008, 동시 접속/호스트 이탈, 보호 기능 검사 |

## 상위 의존성
- **필수 로그인 설계**는 1단계에 문서화하고 4단계에 구현. 따라서 1~3단계는 내부 개발용, 일반 공개/서비스 배포 불가.
- 원문 P0이 로그인 연동 시험을 포함하므로, 내부 P0 통합 검증 전에 인증 시험을 수행해야 한다. 이를 위해 개발 순서를 수정할지는 사용자 승인 후 결정.
- 안전한 프로젝트 저장, 격리, 템플릿 검증은 게임 제작 테스트 이전에 필요하다.
- 공개 공유보다 앞서 업로드 격리와 권한 검증, 콘텐츠/법률 확인이 필요하다.
- 실시간 채팅/멀티플레이는 계정과 신고/차단 체계가 준비된 뒤에만 출시할 수 있다.

## 단계별 운영 공통 규칙
1. 구현할 범위를 문서/작업표로 고정한다.
2. 기존 파일은 보존하고 새 기능은 작은 단위로 구현한다.
3. 개발 후 자동 테스트 + Windows 수동 확인을 실시한다.
4. 성공/미검증/실패를 구분한 완료 보고서를 쓴다.
5. 사용자 승인 후 다음 단계에 진입한다.

## 2단계 이후 중지 원칙
이 문서는 2~5단계를 **계획만** 한다. 2단계 AI 다운로드·실행, 3단계 엔진 연동, 4단계 서버/로그인, 5단계 멀티플레이 구현은 이번 작업에 포함하지 않는다.
